# Image Flow

ChatGPT 이미지 생성의 참조 첨부 → 여러 시안 생성 → 비교 → 수정 → 내보내기를 하나로 연결하는 네이티브 macOS 앱.

**0.11 온보딩 · 사용자 보관함 · 생성 진행 표시.** SwiftUI/AppKit으로 작업 공간을 만들고, ChatGPT 작업이 진행되는 동안만 WKWebView를 사용한다. 자동·빠르게는 ChatGPT를, 고급은 OpenAI 이미지 API를 사용한다. API 사용료는 OpenAI가 직접 청구하며 Image Flow는 어떠한 수수료도 받지 않는다. API 연결은 선택 사항이다. 프롬프트·참조·생성 노드를 연결하는 워크플로 캔버스, 결과 선택과 분기·단계별 재실행, 최대 3개 요청 병렬 실행, 내부 이미지 재첨부, 비교·수정·내보내기를 지원한다. [0.11 사용성과 보관함](docs/V011_PORTABLE_STUDIO.md), [0.10 노드 워크플로](docs/V010_NODE_WORKFLOWS.md), [0.10.1 ChatGPT 호환성 수정과 검증](docs/V0101_CHATGPT_COMPATIBILITY.md)을 참고한다.

## 실행

Xcode 26 이상(macOS 26 이상 SDK와 Swift 6)이 설치된 Mac에서:

```sh
./script/build_and_run.sh
```

Codex의 Run 버튼도 같은 명령을 실행한다. 결과 앱은 `dist/ImageFlow.app`이다. ChatGPT 방식은 왼쪽 아래 **ChatGPT 연결**을 눌러 로그인한다. 로그인 정보는 앱의 WebKit 저장소에 유지된다. API는 생성 방식에서 **고급**을 선택하고 연결 안내에 따라 API 키를 저장한다. ChatGPT 구독과 API 요금은 별도이며, API만 사용할 때는 ChatGPT 로그인이 필요하지 않다.

```sh
./script/build_and_run.sh --connect  # 연결 창도 함께 열기
./script/build_and_run.sh --verify   # 빌드·실행 후 프로세스 확인
swift test                          # 제품 코드의 로컬 자동 테스트
```

macOS 26 이상에서는 시스템 Liquid Glass와 커스텀 유리 컨트롤을 사용한다. macOS 14~15에서는 기존 재질로 표시한다. [패널 재설계와 검증 기록](docs/V08_PANEL_DESIGN.md), [Liquid Glass 도입 기록](docs/V07_LIQUID_GLASS.md)을 참고한다. 빌드 스크립트는 실제 SDK 버전을 링크하고 검사하므로 앱 실행에는 위 스크립트를 사용한다.

최소 배포 대상은 macOS 14지만 실제 실행 검증은 개발 Mac의 macOS 27.2 / Apple Silicon에서만 했다. 현재 번들은 개발용이며 배포 서명·공증을 마치지 않았다.

## 사용 흐름

1. 첫 실행 안내에서 저장 폴더와 생성 연결을 선택한다. 이후 프로젝트를 만들고 오른쪽 **프롬프트 또는 참조 이미지** 영역에 이미지를 드래그하거나 + 버튼으로 가져온다.
2. 프롬프트와 생성 방식, 화면 비율, 배경(자동·투명·불투명), 요청 횟수를 선택한다. 개수는 키보드로도 입력할 수 있다. 여러 방향을 시도하려면 요청별 추가 내용을 줄마다 입력한다.
3. **생성** 또는 **⌘↩**로 작업을 큐에 넣는다. 이후 초안을 수정해도 이미 등록한 작업의 입력은 유지된다.
4. 컬렉션에서 시안을 고르거나 캔버스 카드 상단을 드래그해 배치한다. 두 손가락 스크롤 또는 빈 곳 드래그로 캔버스를 이동한다. **⌘/⇧ 클릭**으로 2~4장을 선택하고 하단의 비교 버튼 또는 ⇧⌘C로 비교한다. 스페이스 또는 더블 클릭으로 크게 본다.
5. 이미지를 오른쪽 **프롬프트·참조 이미지 영역**으로 드래그하거나 클립 아이콘을 눌러 참조로 재사용한다. 이미지 메뉴의 **이 시안 수정**으로 원본을 참조하는 수정본을 만들거나, 별표로 후보를 표시한다.
6. 선택한 결과를 내보내면 이미지 파일과 요청·참조·원본 연결을 담은 `manifest.json`이 함께 저장된다.

생성 방식은 설명이 있는 선택 박스로 제공한다.

| 생성 방식 | 요청당 이미지 수 | 동작 |
|---|---:|---|
| 자동 | 4장 | 가장 적절한 모델을 자동으로 선택한다. |
| 고급 | 기본 2장, 1~10장 | Sunburst·Flare 등 이미지 모델과 옵션을 직접 선택한다. OpenAI가 사용료를 청구하며 앱 수수료는 없다. |
| 빠르게 | 1장 | 기존 Instant 설정으로 빠르게 생성한다. |

요청 횟수 3회라면 자동은 총 12장, API의 요청당 2장은 총 6장, 빠르게는 총 3장을 요청한다. 요청별 변형을 사용하면 비어 있지 않은 줄 수가 요청 횟수다. 새 보관함의 기본값은 자동이며 마지막 선택을 유지한다. 이전 Sunburst 실험 선택은 자동으로 이전하며 유료 API 요청으로 바꾸지 않는다. 이미 대기 중인 이전 요청의 장수와 추론 설정은 유지한다.

**모델을 알 수 없는 결과는 모델 표시 자체를 생략한다.** `gen_size`와 `gen_size_v2`를 모델 식별 근거로 사용하지 않는다. API 결과만 요청에 지정한 모델 이름을 표시한다.

고급의 기본 화면은 모델·품질·이미지 크기·요청당 장수·요청 횟수를 제공한다. 새 설정은 Sunburst, High 품질, 자동 크기, 2장이다. 이미지 API에는 별도 추론 매개변수가 없으며 High는 `quality`로 전송한다. 크기는 ‘1:1 · 1K’, ‘16:9 · 4K’처럼 표시한다. 기존 저장 설정과 대기 중인 요청은 유지한다. **모든 API 옵션…**에서 고정 모델 버전, 사용자 지정 크기, 출력 형식·압축·투명 배경, 마스크, 입력 충실도, 스트리밍·중간 이미지, 콘텐츠 필터, 사용자 식별자를 설정한다. 참조가 있으면 수정 API, 없으면 생성 API를 사용한다. 옵션은 작업에 복사되어 이후 초안 변경의 영향을 받지 않는다. API 키는 macOS 키체인에 저장하며 프로젝트나 내보내기에 포함하지 않는다.

ChatGPT 편집기 종류를 확인해 이미지 생성 도구를 선택한다. 기존 편집기는 **이미지 만들기 (`picture_v2`) Pill 직접 주입**, 새 Markdown 편집기는 **+ → 이미지 생성** 메뉴를 사용한다. 버튼이 활성화될 때까지 기다리고 첨부·설정 후와 전송 직전에 선택된 도구를 재확인한다. 도구 준비가 화면 갱신으로 취소되면 전송 전에만 최대 3회 다시 적용한다. 새 화면의 `blob:` 결과도 메시지별로 식별해 수집하며, 기존 대화에서 결과를 회수할 수 있다. 준비와 전송을 분리하여 요청 기록을 먼저 저장한다. 사용자 프롬프트에 생성 지시문을 덧붙이지 않는다. **빠르게(Instant)는 새 요청·후속 요청에 `n=`를 추가하지 않는다.** 실제 작업 창의 배지를 확인했고, 진행 중 작업에서 **실제 ChatGPT 작업 화면 보기**로 해당 창을 열 수 있다. 명시적으로 선택한 옵션만 `size:1:1`, `transparent_background: true` 또는 `transparent_background: false` 형태로 보낸다. 자동은 해당 옵션을 생략한다. 결과 이미지의 크기와 알파 채널은 서비스가 반환한 원본을 따른다.

확인 알림은 × 버튼으로 닫을 수 있고, 오류·답변은 작업 탭에 그대로 남는다. 새 상태가 도착하면 다시 알린다.

설정에서 절전 모드(1개씩 생성)를 선택할 수 있다. 기본 상한은 3개이며 처음 3개는 함께 시작한다. ChatGPT 워커는 작업 종료 후 다음 작업까지 30~120초 대기한다. API 요청은 이 웹 워커 대기 시간을 적용하지 않는다. 이는 경쟁 프로젝트를 참고한 운영 설정으로, ChatGPT Pro의 공식 동시성 한도를 의미하지 않는다. 한 번에 최대 50회 요청을 큐에 넣는다(자동 방식은 총 200장). 요청한 장수보다 적게 도착하면 받은 원본은 보관하고 누락된 결과의 확인을 요청한다.

앱 종료 등으로 전송 여부가 불확실해지면 자동 재전송하지 않는다. ChatGPT 작업은 카드의 **기존 결과 확인**으로 원래 대화에서 수집하거나 기록을 닫는다. API 작업은 사용량 링크와 요청 ID를 확인하고 기록을 닫는다. 유료 재요청은 사용자가 직접 선택하며 자동 재전송하지 않는다. 기존 결과 확인은 새 생성을 요청하지 않는다. 개별 실패는 다른 작업을 멈추지 않으며, 명시적인 서비스 제한과 로그인 만료는 사유와 함께 새 전송을 정지한다.

외부 첨부도 프로젝트 컬렉션에 **참조** 표시와 함께 남으며 프롬프트에서 제거해도 보관함에는 유지된다. 생성 요청은 컬렉션 안에 요청 장수만큼 자리를 만든다. 4장 요청은 4칸이고, 결과가 도착하면 각 자리를 실제 이미지로 교체한다. 부분 수집·실패 상태도 해당 자리에서 확인하며 클릭하면 작업 기록을 연다. 노드의 생성 결과 영역도 장수만큼 대기 칸을 표시한다.

생성 중에는 전용 애니메이션과 실제 단계를 표시한다. 동작 줄이기 및 비활성 앱에서는 애니메이션을 정지한다. API는 선택한 모델·크기·품질·장수에 따른 **이미지 출력 예상 비용**을 표시하며, 입력 비용은 별도다. 자동 크기는 1K 예시로 표시한다.

프롬프트 옆 **레시피**에서 검색·미리보기·편집·삭제·저장할 수 있다. `{{제품}}`처럼 변수를 만들면 적용 전 입력란이 생긴다. 기본적으로 프롬프트만 적용하고, 생성 설정과 참조 교체는 선택한다. 적용은 ⌘Z로 되돌릴 수 있다.

## 저장·구조

- 저장 위치는 사용자가 선택한다. 기본 권장은 `~/Pictures/Image Flow`이며 설정 → 저장 공간에서 변경·복원할 수 있다. 기존 Application Support 보관함은 첫 안내에서 복사하며 이전 폴더는 보존한다.
- `Originals`: 생성 원본과 첨부 파일. `Metadata`: 이미지별 생성 정보. `ImageFlow.library.json`: 프로젝트·캔버스·레시피·전체 작업을 담은 공개 JSON 복원 파일. `Jobs.json`: 전송 상태 저널. `Receipts`: 이미지 저장 복구 기록. `Thumbnails`: 재생성 가능한 미리보기.
- 앱을 다시 설치한 뒤 **기존 보관함 열기**로 폴더 전체를 선택한다. SwiftData 캐시 없이 JSON과 원본만으로도 복원할 수 있다. API 키와 ChatGPT 로그인은 포함하지 않는다.
- `Sources/FlowCore`: 작업 상태, 입력 스냅샷, 파일 저장·복구·내보내기.
- `Sources/ImageFlow`: 네이티브 화면, 공유 큐, WebKit 세션·워커, DOM 어댑터.
- `config/generation-policy.json`: 운영 설정의 원본. 빌드 스크립트가 앱 리소스에 복사한다.
- `Tests/FlowCoreTests`: 저장·복구·작업 규칙 및 실제 어댑터의 로컬 WebKit 회귀 테스트.

이미지 가져오기는 관리 폴더에 복사하므로 원본 위치가 바뀌어도 참조할 수 있다. 생성 파일은 디코딩·해시 검증 후 저장한다. 생성·수정 시 선택한 참조와 요청이 선택한 ChatGPT 또는 OpenAI API에 전송된다. 로그인 토큰을 앱 자체 데이터베이스나 로그에 추출해 저장하지 않는다.

개발 스크립트는 `--dev-directory .runtime`으로 진단 명령과 상태 파일을 활성화한다. 앱을 직접 열면 이 기능은 비활성이다. `.runtime`은 Git에서 제외하며 계정 화면 진단 파일을 배포 자료에 포함하지 않는다.
