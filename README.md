# Image Flow

ChatGPT 이미지 생성의 참조 첨부 → 여러 시안 생성 → 비교 → 수정 → 내보내기를 하나로 연결하는 네이티브 macOS 앱.

**0.8.1 Studio 타이포그래피 버전.** SwiftUI/AppKit으로 작업 공간을 만들고, 작업이 진행되는 동안만 WKWebView를 사용한다. 앱 전용 ChatGPT 로그인 세션을 사용하며 API 키는 필요하지 않다. 자유 캔버스, 자동·Sunburst (실험)·Instant 생성 방식, 3개 요청 병렬 실행, 내부 이미지 재첨부, 텍스트 답변에 이어서 요청하기를 제공한다. 네이티브 도구 막대·이미지 컬렉션·크기 조절 패널을 사용한다. 키보드 선택, 초안 보존, 2×2 비교와 실행 취소를 제공한다. [0.4 UI 설계](docs/STUDIO_DESIGN.md)와 [0.2 기능 검증](docs/V02_WORKFLOW.md)을 참고한다.

## 실행

Xcode 26 이상(macOS 26 이상 SDK와 Swift 6)이 설치된 Mac에서:

```sh
./script/build_and_run.sh
```

Codex의 Run 버튼도 같은 명령을 실행한다. 결과 앱은 `dist/ImageFlow.app`이다. 처음에는 왼쪽 아래 **ChatGPT 연결**을 눌러 로그인한다. 로그인 정보는 앱의 WebKit 저장소에 유지된다.

```sh
./script/build_and_run.sh --connect  # 연결 창도 함께 열기
./script/build_and_run.sh --verify   # 빌드·실행 후 프로세스 확인
swift test                          # 제품 코드의 로컬 자동 테스트
```

macOS 26 이상에서는 시스템 Liquid Glass와 커스텀 유리 컨트롤을 사용한다. macOS 14~15에서는 기존 재질로 표시한다. [패널 재설계와 검증 기록](docs/V08_PANEL_DESIGN.md), [Liquid Glass 도입 기록](docs/V07_LIQUID_GLASS.md)을 참고한다. 빌드 스크립트는 실제 SDK 버전을 링크하고 검사하므로 앱 실행에는 위 스크립트를 사용한다.

최소 배포 대상은 macOS 14지만 실제 실행 검증은 개발 Mac의 macOS 27.2 / Apple Silicon에서만 했다. 현재 번들은 개발용이며 배포 서명·공증을 마치지 않았다.

## 사용 흐름

1. 프로젝트를 만들고 오른쪽 **참조 이미지** 영역에 이미지를 드래그하거나 + 버튼으로 가져온다.
2. 프롬프트와 생성 방식, 화면 비율, 배경(자동·투명·불투명), 요청 횟수를 선택한다. 개수는 키보드로도 입력할 수 있다. 여러 방향을 시도하려면 요청별 추가 내용을 줄마다 입력한다.
3. **생성** 또는 **⌘↩**로 작업을 큐에 넣는다. 이후 초안을 수정해도 이미 등록한 작업의 입력은 유지된다.
4. 컬렉션에서 시안을 고르거나 캔버스 카드 상단을 드래그해 배치한다. 두 손가락 스크롤 또는 빈 곳 드래그로 캔버스를 이동한다. **⌘/⇧ 클릭**으로 2~4장을 선택하고 하단의 비교 버튼 또는 ⇧⌘C로 비교한다. 스페이스 또는 더블 클릭으로 크게 본다.
5. 이미지를 오른쪽 **참조 이미지 영역**으로 드래그하거나 클립 아이콘을 눌러 참조로 재사용한다. 이미지 메뉴의 **이 시안 수정**으로 원본을 참조하는 수정본을 만들거나, 별표로 후보를 표시한다.
6. 선택한 결과를 내보내면 이미지 파일과 요청·참조·원본 연결을 담은 `manifest.json`이 함께 저장된다.

생성 방식은 설명이 있는 선택 박스로 제공한다.

| 생성 방식 | 요청당 이미지 수 | 동작 |
|---|---:|---|
| 자동 | 4장 | 보통 Flare 2장과 Sunburst 2장이 섞이며 실제 구성은 달라질 수 있다. |
| Sunburst (실험) | 2장 | 높은 확률로 Sunburst가 사용되지만 보장하지 않는다. |
| Instant | 1장 | 가장 빠르고 저렴한 모델을 요청한다. |

요청 횟수 3회라면 자동은 총 12장, Sunburst (실험)은 6장, Instant는 3장을 요청한다. 요청별 변형을 사용하면 비어 있지 않은 줄 수가 요청 횟수다. 전송 프롬프트에 방식별 `n=4`, `n=2`, `n=1`을 붙인다. 새 보관함의 기본값은 자동이며 마지막 선택을 유지한다. 이전 버전의 Sunburst/Flare 선호도는 각각 Sunburst (실험)/Instant로 이전한다. 이미 대기 중인 이전 요청의 장수는 바꾸지 않는다.

**결과 이미지의 모델명은 생성 방식이나 추론 수준에서 추정하지 않는다.** 대화 상세의 각 이미지 `parts[i].metadata.generation`을 원격 파일 ID로 대조한다. `gen_size=smimage`는 Flare, `gen_size=image`는 Sunburst로 표시한다. `gen_size_v2`는 판별에 사용하지 않는다. `gen_size`가 없거나 알 수 없는 값이면 **확인되지 않음**을 표시한다. 정보 패널에서 원시 식별 근거도 볼 수 있다. 과거 이미지는 **모델 정보 확인**을 누르면 원래 대화의 원본 파일 해시와 대조하여 확인한다. 인증 토큰은 웹 페이지 내부 요청에만 쓰며 네이티브 코드·로그·저장 파일로 전달하지 않는다.

ChatGPT 편집기에 **이미지 만들기 (`picture_v2`) Pill과 프롬프트를 직접 주입**하고 `input`·`change` 이벤트로 동기화한다. 첨부·설정 후와 전송 직전에 Pill을 재확인한다. 준비와 전송을 분리하여 요청 기록을 먼저 저장한다. 사용자 프롬프트에 생성 지시문을 덧붙이지 않는다. 명시적으로 선택한 옵션만 `size:1:1`, `transparent_background: true` 또는 `transparent_background: false` 형태로 보낸다. 자동은 해당 옵션을 생략한다. 결과 이미지의 크기와 알파 채널은 서비스가 반환한 원본을 따른다.

확인 알림은 × 버튼으로 닫을 수 있고, 오류·답변은 작업 탭에 그대로 남는다. 새 상태가 도착하면 다시 알린다.

설정에서 절전 모드(1개씩 생성)를 선택할 수 있다. 기본 상한은 3개이며 처음 3개는 함께 시작한다. 각 워커는 작업 종료 후 다음 작업까지 30~120초 대기한다. 이는 경쟁 프로젝트를 참고한 운영 설정으로, ChatGPT Pro의 공식 동시성 한도를 의미하지 않는다. 한 번에 최대 50회 요청을 큐에 넣는다(자동 방식은 총 200장). 요청한 장수보다 적게 도착하면 받은 원본은 보관하고 누락된 결과의 확인을 요청한다.

앱 종료 등으로 전송 여부가 불확실해지면 자동 재전송하지 않는다. 작업 카드의 **기존 결과 확인**으로 원래 대화에서 수집하거나 기록을 닫는다. 기존 결과 확인은 새 생성을 요청하지 않는다. 개별 실패는 다른 작업을 멈추지 않으며, 명시적인 서비스 제한과 로그인 만료는 사유와 함께 새 전송을 정지한다.

## 저장·구조

- `~/Library/Application Support/ImageFlow`: SwiftData 프로젝트·자산 목록, `Jobs.json` 작업 이력, `Originals` 이미지 파일, `Thumbnails` 미리보기, `Receipts` 저장 복구 기록.
- `Sources/FlowCore`: 작업 상태, 입력 스냅샷, 파일 저장·복구·내보내기.
- `Sources/ImageFlow`: 네이티브 화면, 공유 큐, WebKit 세션·워커, DOM 어댑터.
- `config/generation-policy.json`: 운영 설정의 원본. 빌드 스크립트가 앱 리소스에 복사한다.
- `Tests/FlowCoreTests`: 저장·복구·작업 규칙 및 실제 어댑터의 로컬 WebKit 회귀 테스트.

이미지 가져오기는 관리 폴더에 복사하므로 원본 위치가 바뀌어도 참조할 수 있다. 생성 파일은 디코딩·해시 검증 후 저장한다. 생성·수정 시 선택한 참조와 요청이 ChatGPT에 전송된다. 로그인 토큰을 앱 자체 데이터베이스나 로그에 추출해 저장하지 않는다.

개발 스크립트는 `--dev-directory .runtime`으로 진단 명령과 상태 파일을 활성화한다. 앱을 직접 열면 이 기능은 비활성이다. `.runtime`은 Git에서 제외하며 계정 화면 진단 파일을 배포 자료에 포함하지 않는다.
