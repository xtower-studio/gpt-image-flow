# 구현 착수 전 검토 결과

날짜: 2026-09-19. 판정: **네이티브 앱 구현 착수 가능**.

후속: 사용자 승인 후 제품 알파를 구현하고 실제 생성 검증을 진행했다. 현재 상태는 [ALPHA_VALIDATION.md](ALPHA_VALIDATION.md)에 기록한다. 아래 내용은 구현 전 검토 시점의 증거다.

사용자의 지시에 따라 생성 한도·동시성 부하 테스트는 하지 않았다. ChatGPT 생성 요청, 참조 파일의 외부 업로드, 계정 로그인 조작은 이번 검증에 포함하지 않았다. 운영 설정은 지정된 경쟁 프로젝트를 근거로 고정했고, 플랫폼 기능과 스케줄링·복구 규칙은 별도의 로컬 검증 프로그램으로 확인했다.

이 문서는 구현 전 의사결정을 마친 결과다. 서비스 전체 연동, 모든 지원 OS, 완성 앱의 자원 사용량, 공개 배포 적합성까지 검증했다는 뜻은 아니다. 이들은 아래의 구현·출시 단계 수용 기준으로 연결했다.

## 1. 확인한 원본과 증거 수준

- 저장소: [ManiacMike/chatgpt-endless-canvas](https://github.com/ManiacMike/chatgpt-endless-canvas).
- 검토 커밋: [`7783f02518d3d1878f3729e80b8499fb566d15e9`](https://github.com/ManiacMike/chatgpt-endless-canvas/commit/7783f02518d3d1878f3729e80b8499fb566d15e9), 서버 버전 1.2.0.
- 코드·README·커밋 기록을 확인했다. 저장소에서 Pro 동시성 상한에 대한 재현 가능한 실험 로그나 자동 테스트 모음은 찾지 못했다.
- 따라서 **3은 채택할 운영 기본값이며 GPT Pro의 공식 최대치라는 결론은 아니다**. 코드는 환경변수로 3보다 큰 수도 받는다. 우리 앱은 초기 지원 범위를 3으로 제한한다.
- 파일 SHA-256과 코드 위치는 [source-audit.json](evidence/source-audit.json)에 보존했다. 외부 코드를 실행하지 않고 AST 파싱과 소스 조건 확인으로 13개 항목을 점검했다.

## 2. 채택하는 운영 설정

실행 가능한 단일 설정 원본: [generation-policy.json](../config/generation-policy.json).

| 항목 | 결정 | 근거와 의미 |
| --- | --- | --- |
| 기본 동시 생성 | 3개 | upstream `BOARD_WORKERS=3`, `board_server.py:93` |
| 초기 앱 상한 | 3개 | 운영 기준을 넘는 탐색은 하지 않는 제품 결정 |
| 절전 모드 | 1개 | 낮은 자원 사용을 위한 우리 앱의 선택 |
| 한 번에 큐에 넣는 작업 | 최대 50개 | upstream 앱의 요청 검증, `board_server.py:535`; 서비스 쿼터가 아님 |
| 새 요청 사이 대기 | 30~120초 | upstream 기본 범위를 채택하되 계정 전체 전송에 적용 |
| 생성 관찰 타임아웃 | 420초 | upstream 서버가 generator에 전달하는 값, `board_server.py:326` |
| 작업 watchdog | 500초 | upstream subprocess timeout, `board_server.py:333`; 앱에서는 복구 상태로 전환하는 기준 |
| 불확실한 요청 자동 재전송 | 하지 않음 | 중복 생성 방지 |
| 서비스 제한·세션 만료 | 새 전송 정지 | 진행 중 요청의 식별 정보와 자산은 유지 |

upstream의 30~120초 sleep은 **각 워커 내부**에 있다(`board_server.py:376`). 여러 워커가 비슷한 시점에 전송할 수 있으므로 이를 계정 전체 최소 간격으로 해석하면 안 된다. 우리 앱은 전송 간격을 계정 전체 gate에서 관리한다. 첫 작업은 바로 시작하고, 이후 작업은 지정 간격과 빈 슬롯을 모두 만족할 때 시작한다. 생성이 오래 걸리면 최대 3개가 겹칠 수 있으며 항상 3개를 동시에 가동하는 것은 아니다.

이 gate는 우리 앱의 창·프로젝트 전체를 통제한다. 사용자가 다른 브라우저에서 보낸 요청의 실행 수까지 알 수 있다고 가정하지 않는다.

일일/3시간 이미지 쿼터, 서비스 자체 파일 용량·참조 개수 상한, 계정별 동적 제한은 upstream에서 확정할 수 없다. 서버 코드의 50MB 업로드 제한이나 500건 이력 보존을 ChatGPT 제한으로 옮기지 않는다. 서비스가 알려주는 제한 상태를 우선하고 임의의 남은 할당량을 UI에 표시하지 않는다.

| 대화 sidecar는 빨리 쓰지만 부모 큐의 conversationId 반영은 subprocess 종료 후 | 대화 ID 발견 즉시 journal 저장. 제출 후 ID 확보 전 종료는 불확실한 요청으로 복구 |

소스 전체를 제품 코드로 복사하지 않았다. 비교 코드의 라이선스와 출처는 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)에 남겼다.

## 4. 로컬 실행 결과

환경: Apple Silicon arm64, macOS 27.2 (26B5086k), Swift 6.4, macOS SDK 27.0. 패키지는 macOS 14 deployment target으로 빌드했다. **macOS 14에서 실제 실행한 것은 아니다.**

검증 프로그램은 nonpersistent WKWebsiteDataStore와 합성 HTML만 사용한다. 결과 선택 시험의 이미지 속성도 로컬에서 정의하므로 외부 이미지 요청이 발생하지 않는다.

| 검증 | 결과 | 증거 범위 |
| --- | --- | --- |
| 고정 upstream 소스 감사 | 13개 확인 | 설정·구현 경로의 정적 증거 |
| Swift 단위 검증 | 11/11 통과 | 3개 슬롯, 1개 절전, 계정 간격, 100개 경합 요청, 중복·stale 완료, pause, gate 복원, batch, 파일 해시, SwiftData |
| 실제 SIGKILL·별도 프로세스 복구 | 7/7 통과 | queued / uploading / submitting / submitted / generating / collecting / saved |
| 로컬 WebKit 기능 | 10/10 통과 | 아래 첨부·다운로드·짧은 숨김 동작 |
| 합성 DOM 결과 선택 | 8/8 통과 | 새 응답 연결·이전 파일 제외·다중 결과·미완성 제외 등 계약 |

원본 증거: [Swift 테스트 로그](evidence/swift-tests.log), [강제 종료 결과](evidence/crash-report.json), [WebKit/DOM 결과](evidence/webkit-report.json). WebKit JSON에는 18개 기능 검증 외에 실행 종료 확인 1개가 추가되어 있다.

WebKit에서 확인한 동작:

1. 한글·공백이 포함된 PNG 파일을 open-panel delegate로 제공하고 JavaScript에서 같은 바이트 읽기.
2. PNG와 JPEG를 동시에 첨부하고 순서·파일명·바이트 일치 확인.
3. 동일 파일 세트를 새 입력에 다시 첨부.
4. 같은 웹 저장소를 공유하는 웹뷰 3개가 서로 다른 첨부 상태 유지.
5. 없는 파일 선택 시 파일을 넘기지 않음.
6. 선택 취소 시 비어 있는 입력 유지.
7. 최소화 중 파일 첨부.
8. 창 숨김 중 파일 첨부.
9. 창 숨김 후 10초 동안 타이머가 진행하는지 확인.
10. 로컬 Blob을 WKDownload로 저장하고 원본 PNG 바이트와 대조.

### 중요한 발견: 숨김 타이머는 느려질 수 있다

마지막 시험에서는 250ms 주기 타이머가 숨김 10초 동안 10회 실행됐다. 앞선 로컬 실행에서는 33회였다. **백그라운드에서 고정 속도로 실행된다는 가정을 제거한다.** 이는 보고서의 5초 최소화 결과를 부정하는 것이 아니라, 최소화와 숨김·실행 시점에 따라 관찰이 다르다는 증거다.

구현은 `MutationObserver` 알림에 네이티브 watchdog을 조합한다. 네이티브 타이머도 시스템 잠자기 중 계속 실행된다고 가정하지 않는다. 깨어남·활성화·웹 프로세스 종료 시 대화 상태를 다시 대조한다. 숨김 상태에서 작업이 빨리 끝난다는 보장은 하지 않는다.

### 결과 선택 계약

현재 ChatGPT DOM을 복사해 테스트한 것은 아니다. 합성 DOM에서 다음 논리를 검증했다: 잘못된 대화 거절, 해당 assistant 응답만 읽기, user 참조 제외, URL 토큰이 바뀌어도 이전 file ID 제외, 여러 결과 보존, Stop 버튼 존재 시 보류, 이미지 디코딩 미완료 시 보류, URL 안정화 전 보류.

이 계약은 실제 어댑터의 회귀 테스트 요구사항이다. DOM 선택자가 현재 서비스와 맞는지는 첫 통합에서 확인한다.

### 저장·복구 계약

SwiftData에는 명시적으로 save한 메타데이터를 container 재생성 후 다시 읽을 수 있었다. 제출·대화 식별·결과 파일 경계는 별도 JSON journal로 시험했다. 외부 프로세스를 SIGKILL로 종료한 뒤 새 프로세스에서 같은 journal을 읽었다.

- 제출 전: 준비 단계부터 재개.
- 전송 시도 후 대화 ID 없음: `needsReview`. 자동 재전송하지 않음.
- 대화 ID 있고 로컬 결과 없음: 기존 대화 결과 수집.
- 파일은 저장됐지만 완료 DB 기록 전 종료: 해시가 맞으면 저장 완료로 복구.
- 이미 저장 완료: 그대로 재사용.

전원 차단, 디스크 오류, OS 파일시스템 손상에 대한 내구성까지 입증한 것은 아니다. 새 앱의 실제 저장 계층에서도 동일한 중단 시험을 유지한다.

## 5. 확정한 구현 결정

- Swift 6, SwiftUI 기본 UI, WebKit/AppKit 최소 브리지. 별도 Python·Chrome은 제품 런타임에 포함하지 않는다.
- 기본 최대 3개 워커를 필요할 때 만들고 유휴 시 해제한다. 절전 모드 1개. 창마다 워커 풀을 만들지 않는다.
- 한 워커가 실행 중에는 다른 작업이나 사용자 탐색이 그 워커의 대화를 바꾸지 못하게 한다. 진단용 대화 열기는 분리한다.
- SwiftData는 프로젝트·레시피·자산 메타데이터에 사용하고, 전송 직전 기록과 복구 경계에는 명시적 job journal을 둔다.
- journal을 복구의 기준으로 사용하며 메타데이터는 idempotent upsert로 맞춘다. 이미지 파일은 UUID·해시로 식별한다.
- gate의 활성 슬롯·이미 제출한 job ID·다음 전송 시각을 저장한다. 재시작 후 원격 작업 확인 전 새 전송을 시작하지 않는다.
- 생성 지연을 곧바로 rate limit으로 단정하지 않는다. 명시적 제한과 무응답을 구분하되 불확실하면 새 전송을 정지한다.
- 워커 3개의 메모리 예산은 단일 워커 예산과 따로 평가한다. 빈 로컬 웹뷰 3개 시험으로 ChatGPT 세션 3개의 메모리를 추정하지 않는다.
- 자동화와 저장 로직은 UI 프로토타입과 분리해 실제 provider 없이도 전체 UX를 개발할 수 있게 한다.

## 6. 구현 전 완료 항목과 이후 수용 기준

| 항목 | 처리 |
| --- | --- |
| 경쟁 프로젝트 식별·버전 고정 | 완료 |
| 생성 정책·타임아웃·오류 처리 결정 | 완료; 설정 JSON 및 테스트로 고정 |
| 로컬 도구·컴파일·앱 번들 실행 경로 | 완료; Codex Run은 검증 앱 실행 |
| 파일 첨부·다운로드 플랫폼 경로 | 로컬 fixture 검증 완료 |
| 스케줄링·결과 선택·복구 규칙 | 로컬 검증 완료 |
| Git·디렉터리·검증 재실행 문서 | 완료 |
| 로그인·실제 생성·페이지 내 원본 수집 | 사용자 제공 보고서의 선행 증거를 채택. 이번에는 재실행하지 않음 |
| 실제 ChatGPT 업로드 처리·인증된 WKDownload·최신 DOM | 첫 실제 어댑터 통합의 수용 기준. 로컬 검증으로 대체됐다고 주장하지 않음 |
| 장시간 실행·지원 최소 OS·실제 3세션 메모리 | Alpha/Beta 수용 기준. 서비스 한도 부하 테스트는 요구하지 않음 |
| 디자인 사용자 테스트 | 네이티브 UX 프로토타입 완성 후 수행 |
| 서비스 조건·공증·공개 배포 적합성 | 공개 배포 전 별도 확인. 이번 결과는 공개 배포 승인 아님 |

**다음 단계는 네이티브 작업 보드·작성기·비교 화면과 가짜 생성 provider를 만드는 것이다.** 실제 연동은 확정된 3개 워커 정책과 동일한 계약으로 연결한다. 설정값을 정하기 위해 추가 이미지 한도 시험을 할 필요는 없다.

개발 도구는 Xcode/Swift와 Python 3이다. Python은 검증 스크립트용이고 제품 의존성이 아니다. 네트워크가 필요한 단계는 참조 소스 확보뿐이다. 생성된 번들·중간 산출물은 Git에서 제외하고, 이 문서에 연결한 검증 증거만 보존한다.
