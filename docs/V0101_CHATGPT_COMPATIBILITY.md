# 0.10.1 · ChatGPT 입력창 호환성 수정

2026-09-25~26 실제 로그인된 WKWebView에서 확인했다.

## 원인

새 ChatGPT Markdown 편집기는 기존 `picture_v2` 인라인 Pill을 일반 텍스트로 변환한다. `#prompt-textarea`, 기존 전송 버튼 test ID, 추론 버튼 CSS 클래스도 더 이상 제공하지 않는다. 편집기 DOM은 도구 버튼이 활성화되기 전에 나타나므로 DOM 존재만으로 준비 완료를 판정하면 너무 일찍 조작한다.

## 수정

- 기존 편집기의 직접 Pill 주입은 유지한다. 새 `data-composer-markdown` 편집기에서는 + 메뉴의 이미지 생성 도구를 선택하고, 입력창 밖의 선택된 도구 버튼을 확인한다.
- 도구·추론 버튼이 활성화될 때까지 준비를 기다린다. 화면 갱신으로 도구 적용이 취소된 경우에는 첨부·전송 전에만 최대 3회 다시 준비한다. 전송 자체는 재시도하지 않는다.
- 현재 편집기 form 안에서 전송·추론·첨부 컨트롤을 찾는다. 첨부 및 추론 설정 후와 전송 직전에도 이미지 도구 선택을 확인한다.
- 새 결과 화면의 `blob:` 원본, 큰 프리뷰와 썸네일 목록을 함께 읽는다. 메시지 ID와 이미지 순번으로 중복을 제거하고, 페이지를 다시 열어도 같은 결과를 식별한다. 다운로드는 해당 대화의 확인된 생성 이미지로 제한한다.
- 새 사용자 메시지·답변 구조와 Markdown 응답을 읽어 텍스트 응답 후속 작업을 유지한다.
- 준비 실패 메시지에서 입력창·도구 메뉴·선택 확인 실패를 구분하고, 전송 전 실패라는 점을 알린다.

## 검증

- `swift test`: 70개 통과. 이전/현재 편집기, Pill 거부 시 전환, 비활성 컨트롤, 선택 해제 후 전송 차단, 프롬프트 보존, blob 다운로드, 참조 제외, 갤러리 중복 제거, 텍스트 응답, 재수집 식별을 포함한다.
- 실제 ChatGPT: 빠르게 1장 및 참조 이미지를 넣은 자동 4장 생성·원본 저장 완료. 총 2회 전송, 5장. API 유료 요청 없음.
- 부분 수집된 자동 요청은 기존 대화에서 재생성 없이 총 4장으로 복구했다.
- 전송 없는 3개 워커 동시 준비: 자동+참조 1개, 빠르게 2개 모두 성공. 추론 적용값 3/0/0 확인.
- `script/build_and_run.sh --verify`: 0.10.1 빌드·서명 검사·실행 성공.

웹 화면 구조는 서비스 변경에 따라 다시 달라질 수 있다. 이번 검증은 현재 계정의 한국어 새 화면과 로컬 이전 화면 fixture를 대상으로 했다. 도구 선택을 확인할 수 없으면 요청을 보내지 않는다.
