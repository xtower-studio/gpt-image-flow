# 0.11.1 — 본문 내 이미지 도구 배지 보존

2026-10-06 확인한 ChatGPT 화면은 `data-composer-markdown` 편집기 본문 안에 `picture_v2` 배지를 넣는다. 9월의 입력창 하단 제거 버튼과 달리 `data-prompt-link-href="chatgpt-system-hint://picture_v2"`를 가진 실제 인라인 노드다. 메뉴 항목은 여전히 + 메뉴의 ‘이미지 생성’이다.

## 수정

- 프롬프트를 교체할 때 이미 선택된 실제 배지를 복제해 새 본문에 보존한다. 기존 구현은 현대 편집기의 본문을 통째로 바꾸면서 배지를 지웠다.
- 배지의 명시적 도구 링크도 선택 증거로 인식한다. 일반 프롬프트에 ‘이미지 생성’이라고 쓴 텍스트는 선택 증거로 인정하지 않는다.
- 네이티브 메뉴를 누른 후 선택 반영 대기를 2초에서 5초로 늘렸다. 배지가 나타난 뒤에도 잠시 기다려 선택 유지 여부를 확인한다.
- 첨부·추론 설정 후 입력창이 다시 만들어져 선택이 사라지면, 본문과 파일을 건드리지 않고 전송 전에만 다시 선택한다.
- 전송 직전 엄격한 검증은 유지한다. 선택을 확인하지 못한 요청은 보내지 않으며, 이미 보낸 요청을 자동 재전송하지 않는다.

## 검증 범위

신고 당시의 간헐적 오류는 현재 로그인 화면에서 즉시 재현되지 않았다. 수정 전에도 단일 준비 및 3개 동시 준비는 통과했다. 따라서 과거 실패의 단일 원인으로 단정하지 않는다. 현재 실제 DOM에서 확인한 인라인 배지를 기존 코드가 제거하는 경로를 보완했다.

- 전체 기존·신규 테스트 80개 통과 후, 늦은 배지 반영 회귀 테스트를 추가해 어댑터 테스트를 별도 실행했다.
- 인라인 배지 보존, 프롬프트를 유지한 도구 재선택, 2.5초 후 적용되는 도구 대기, 미선택 시 전송 차단을 검증한다.
- 수정된 앱에서 자동/Instant를 포함한 3개 동시 준비 통과. 자동 요청은 알려진 검증용 참조 이미지도 첨부했다.
- 실제 화면 캡처와 DOM에서 `picture_v2` 배지 및 도구 링크를 확인했다. 개인 계정 화면은 Git에 포함하지 않고 `.runtime`에만 보관한다.
- 실제 자동 4장(참조 포함)과 Instant 1장, 총 5장의 생성·수집·저장을 확인했다. 두 요청 모두 오류 없이 `saved`로 완료됐다. 추가 유료 API 요청은 없었다.
- 늦은 선택 반영 테스트를 포함한 어댑터 테스트 18개 통과. 빌드·실행은 `script/build_and_run.sh --verify`로 검증했다.
