# 0.13.0 — 이미지 중심 작업 공간

## 사용 방식

- 프로젝트별 누적 요청 번호와 결과 순서로 1-1, 1-2, 2-1처럼 이름을 붙인다. 취소·재정렬·재시작 후에도 번호를 재사용하지 않는다.
- 이름·즐겨찾기·설정을 이미지 안으로 이동했다. 컬렉션의 카드 아래 설명과 도구 줄을 제거했다. 이미지 이름 클릭 또는 Return으로 실제 파일명을 바꾼다.
- 카드 도구의 클릭 영역은 32×32pt. 이미지는 컬렉션에서 프레임을 채워 표시하며 확대 보기는 전체 원본을 표시한다.
- Space로 크게 열고 ←/→ 및 화면 화살표로 현재 필터의 앞뒤 이미지를 본다. Space/Esc로 닫는다. 비교 기능은 별도로 유지한다.
- UI의 글자는 기본 14pt, 보조 정보는 13pt 이상이다. 중복 개수, 카드별 픽셀 크기, 고정 동시 실행 안내 등 반복 텍스트를 제거했다.

Apple HIG의 [Typography](https://developer.apple.com/design/human-interface-guidelines/typography)와 [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)를 참고했다. HIG의 macOS 기본 글자 크기는 13pt, 최소는 10pt이고, 기본 컨트롤 크기는 28×28pt이다. 이번 제품 기준은 최소값보다 읽기 쉬운 크기를 사용한다.

## 보관함 v3

- 최상위: 프로젝트 폴더와 숨김 `.imageflow`만 둔다.
- 프로젝트: 생성 원본·첨부 원본과 숨김 `.imageflow`만 둔다. JSON은 `.imageflow/images/<asset ID>.json`, 프로젝트 설정은 `.imageflow/project.json`이다.
- 전체 manifest, 작업 저널, 저장 영수증과 SwiftData 캐시는 최상위 `.imageflow`에 둔다. 이전 manifest 및 데이터베이스 백업도 숨김 폴더에 보존한다.
- v1·v2를 읽고 원본 복사·SHA-256 검증·복구 경로 기록 후 이전 파일을 정리한다. Finder에서 하위 폴더로 옮긴 파일은 ID와 해시를 모두 확인해 복구한다.
- 동명 파일은 숫자 접미사를 붙이고 덮어쓰지 않는다. 파일명 변경도 새 파일 복사·검증·manifest 저장을 마친 뒤 이전 경로를 제거한다.
- 백업은 숨김 파일을 포함한 전체 보관함 폴더를 복사한다.

## 검증

- 번호 할당, 취소·재정렬·재시작, 사용자 지정 이름 보존, 실제 파일명 변경, 동명 파일 보호, v1·v2 이전, 수동 이동한 원본 복구와 숨김 구조를 자동 테스트한다.
- 실제 보관함의 복사본에서 219개 원본의 SHA-256을 검증했다. 이 중 기록된 경로에서 이동한 28개도 찾았다. 검증 복사본의 대기열은 일시정지했으며 새 이미지 생성은 요청하지 않았다.
- 앱에서 Space 열기, 방향키 이동, Space 닫기 및 카드 오버레이 조작을 확인했다.
- Developer ID 인증서와 공증 환경이 아직 준비되지 않아 DMG는 preview로 구분한다.

최종 앱으로 교체한 실제 보관함에서도 기존 원본 219개의 해시가 모두 유지됐고, 최상위에는 프로젝트 폴더 19개만 보인다. 기존 대기 요청 3개는 원래 대기열에 따라 재개됐다. 새로운 검증용 생성 요청은 추가하지 않았다. 전체 자동 테스트 88개를 통과했다.
