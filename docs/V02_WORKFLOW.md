# Image Flow 0.2 — 캔버스와 병렬 워크플로

이 버전은 기존 로컬 알파에 자유 배치 캔버스, 추론 선택, 실제 병렬 생성, 내부 재첨부, 답변 후속 요청을 연결한다.

## 사용 흐름

- **캔버스 / 그리드**: 프로젝트 상단에서 전환한다. 캔버스 카드 상단을 드래그해 배치하고, 빈 곳을 드래그해 이동한다. 여러 카드를 ⌘/⇧ 클릭해 함께 옮길 수 있다. 확대·축소, 핀치, 전체 보기, 정렬을 제공한다. 배치와 화면 위치는 프로젝트별로 저장한다. 선은 참조·수정·후속 요청 관계를 표시하며, ComfyUI의 노드 실행 그래프를 가져오는 기능은 아니다.
- **모델 · 추론 수준**: 작성기에서 0(Instant)~4(최대)를 선택한다. 작업 등록 시 선택값을 고정하고 전송 전 ChatGPT의 실제 슬라이더 값을 적용·확인한다. 내부 모델 이름을 고정해서 호출하는 API가 아니라 서비스 UI의 추론 설정을 사용한다.
- **동시 생성**: 일반 모드는 3개, 절전 모드는 1개다. 첫 작업 3개는 함께 시작하고, 완료한 워커만 다음 작업 전 30~120초 대기한다. 기존의 앱 전체 전송 간격을 제거했다. 같은 대화에 보내는 후속 요청은 겹치지 않게 한다.
- **이미지 재사용**: 이미지 자체를 작성기에 드래그하거나 하단 클립 아이콘을 누른다. 작성기 입력창에 파일을 놓거나 파일을 복사해 붙여넣어도 참조로 추가한다. 앱 내부 이미지 파일은 복제하지 않고 기존 자산을 참조한다.
- **이미지 도구**: 크게 보기, 참조로 사용, 수정, 후보 표시, 복사, 내보내기, Finder에서 보기, 숨기기를 제공한다. 숨기기는 파일을 지우지 않으며 안내줄의 되돌리기 또는 설정의 전체 복원으로 취소할 수 있다.
- **레시피**: 작성기의 레시피 메뉴에서 요청·참조·비율·추론·시안 설정을 이름 붙여 저장하고 재사용한다.
- **실패·답변**: 실패한 카드에 원인을 표시하고 다른 대기 작업은 계속한다. 이미지 대신 답변이 오면 카드와 우측 작업 패널에서 내용을 읽고 같은 대화로 후속 요청을 보낸다. 후속 작업은 이전 이미지를 결과로 다시 저장하지 않는다.

로그인 만료와 서비스의 명시적인 사용 제한은 큐 전체의 진행을 막는 사유이므로 이유를 표시하고 새 전송을 정지한다. 전송 여부를 확정할 수 없는 작업은 결과 확인 대상으로 남기며 자동 재전송하지 않는다. 다른 대화의 작업은 계속 진행한다.

## 데이터 호환

기존 프로젝트, 생성 파일, 작업 이력을 유지한다. 새 모델·캔버스·답변 필드는 선택적 필드로 추가했다. 작업 cooldown은 워커별로 저장한다. 기존 버전에서 일시정지한 큐는 사용자가 계속을 누르면 재개한다. 구현 전 데이터 백업은 로컬 `.runtime/backup-v01-*`에 보관했다.

## 검증

실제 ChatGPT UI에서 수준 0~4의 선택·읽기 확인을 수행했다. 관찰된 표시는 Instant, 중간, High, 매우 높음, 6 Pro였다. 이는 해당 계정·시점의 UI 표시이며 영구 모델 라우팅 보장이 아니다.

실제 세 요청에 0·2·4를 각각 적용해 동시에 `generating` 상태인 구간을 기록했고, 세 요청 모두 결과 이미지 저장에 성공했다. 생성 한도를 찾기 위한 부하 시험은 수행하지 않았다.

추가 검증 결과와 정확한 테스트 수는 이 문서의 최종 검증 기록 및 `docs/evidence/v02-validation.json`에 기록한다. 계정의 다른 대화 내용은 공개 증거에 포함하지 않는다.

최종 검증: **자동 테스트 20개 통과**. 3개가 동시에 생성 중인 상태를 2초 간격 기록에서 7회 관찰했다. 수준 0·2·4의 이미지 3장과 같은 대화의 후속 이미지 1장을 저장했다. 텍스트 응답 2건은 전체 내용이 저장·표시됐다. 첫 건은 디버깅 중 기존 대화에서 회수했고, 두 번째는 보완된 엔진에서 자동 완료했다. 참조 누락 실패 1건을 넣었을 때 큐는 정지하지 않았고 후속 작업이 계속됐다.

숨김 웹뷰에서 텍스트 스트림 렌더링이 갱신되지 않는 현상을 관찰해, 진행 신호가 45초간 변하지 않으면 이미 알고 있는 대화 URL을 다시 읽도록 했다. 이 과정에서는 요청을 다시 전송하지 않는다. 답변이 표시됐다고 단정하기 전에 실제 내용을 읽고 안정화 상태를 확인한다.

내부 이미지 파일을 두 번 재첨부했을 때 자산 수가 늘지 않고 참조가 한 번만 추가되는 것을 앱에서 확인했다. 제공하는 드래그 항목은 `public.file-url` / `public.url`이며 입력창은 AppKit에서 파일 드롭·파일 붙여넣기를 참조 첨부로 처리한다. 마우스 드래그 제스처 전체를 자동화한 테스트는 아니다.

재실행 후 캔버스 좌표·확대·참조·레시피·숨기기 취소 상태가 유지됐다. 이전 버전의 사용자 작업 12건과 이미지 파일 14개의 바이트도 보존됐다. 최종 네이티브 화면에서 이미지 하단 도구, 캔버스 카드, 답변·후속 입력 패널을 확인했다.

검증 환경은 개발 Mac 1대이며, 타 macOS 버전 검증·장시간 성능 비교·서명·공증은 이번 기능 구현 범위에 포함하지 않았다. 비교 이미지 원본 스트리밍 다운로드와 고급 마스킹 편집 등 장기 계획 전체를 완료했다는 의미는 아니다.
