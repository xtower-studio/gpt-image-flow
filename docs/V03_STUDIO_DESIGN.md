# Image Flow 0.3 — Studio UI

디자이너가 시안을 만들고, 비교하고, 다음 방향으로 이어가는 과정에 맞춰 작업 공간을 다시 구성했다.

## 화면 구조

- 왼쪽: 프로젝트 목록과 ChatGPT 연결. macOS 네이티브 사이드바를 유지한다.
- 중앙: 큰 이미지 중심의 **컬렉션**과 자유 배치 **캔버스**. 컬렉션은 생성 묶음별 반복 헤더를 없앤 연락판 형태다. 기본 크기에서는 좁은 창에서도 두 열을 유지한다.
- 오른쪽: **만들기 / 이미지 정보 / 답변**을 하나의 작업 패널로 통합한다. 패널 접기와 탭 전환 중에도 현재 입력을 유지한다.
- 하단: 준비·진행·대기 상태를 얇게 표시하고, 상세 작업 기록은 팝오버에서 연다.

## 인터랙션

이미지 하단에서 미리보기, 참조 첨부, 수정, 후보 표시, 내보내기를 실행한다. 선택하면 보드 안에 도구 막대가 나타난다. ⌘/⇧ 클릭으로 여러 장을 선택하고 2~4장을 비교한다. Space 또는 더블 클릭으로 원본을 본다. 비교 화면에서는 함께 확대하고 후보를 표시하며 필요할 때 프롬프트를 펼친다.

만들기 패널은 참조 → 프롬프트 → 추론 수준 → 비율 → 개수 순서다. 시안별 변형과 레시피는 필요할 때 펼친다. 생성 버튼은 패널 하단에 고정한다. 참조 파일을 가져오는 동안은 생성 버튼을 비활성화해 첨부가 빠진 요청을 막는다.

실패와 텍스트 답변은 컬렉션의 별도 목록으로 표시한다. 해당 항목을 누르면 같은 작업 공간의 답변 탭에서 내용을 읽고 후속 요청을 보낸다. 전송 여부가 불확실한 작업의 기존 복구 절차는 유지한다.

캔버스는 빈 공간 드래그, 두 손가락 스크롤, 핀치, ⌘+스크롤을 지원한다. 카드 상단은 배치, 이미지 자체는 파일 드래그로 구분한다. 이동 저장은 300ms 지연으로 묶는다. 이벤트 모니터는 앱 내부 캔버스 영역에만 반응하고 뷰 해제 시 제거한다.

## 시각 원칙

이미지 색을 방해하지 않는 중성 배경, 얇은 구분선, 일관된 여백과 아이콘 크기를 사용한다. 기본 행동에는 높은 명도 대비를 주고 선택·포커스에는 시스템 강조색을 쓴다. 이미지 비율은 자르지 않고 보존한다. 밝은 모드와 어두운 모드 모두 시스템 색에 맞춰 적응한다.

새 생성 엔진이나 웹 UI를 추가하지 않는다. 기존 썸네일 캐시, LazyVGrid, 캔버스 화면 밖 노드 제외를 유지한다. 생성·데이터 모델과 기존 파일 형식은 바꾸지 않았다.

- `swift test`: 기존 저장·복구·어댑터·병렬 워크플로 테스트 20개 통과.
- `build_and_run.sh --verify`: 0.3.0 앱 빌드·실행 확인.
- 실제 NSWindow 화면: 1360×860 밝은/어두운 모드, 1000×720의 두 열 컬렉션과 검색, 빈 프로젝트, 캔버스 전체 보기, 이미지 정보, 답변, 비교 화면 확인.
- macOS 접근성 UI 조작: 수정 초안 `draft123` 입력 → 정보 탭 → 만들기 탭 → 패널 접기/열기 후 같은 내용 유지 확인. 검증 초안은 수정 모드를 닫아 제거했다.
- 검색을 열었을 때 실제 포커스가 검색 텍스트 필드로 이동하는 것 확인.
- 기존 이미지 18개와 작업 19개 유지. 이번 UI 검증에서 새 생성 요청은 보내지 않았다. 실제 병렬 생성 검증은 [0.2 기록](V02_WORKFLOW.md)을 참조한다.
- 유휴 상태 한 시점의 앱 프로세스: CPU 0.0%, RSS 약 175 MiB. 장시간 성능/누수 벤치마크 결과는 아니다.

밝은/어두운 모드와 주요 화면 원본 캡처는 개발 작업 폴더 `.runtime/studio-*.png`에 있다. 대표 화면은 [studio-workspace.png](evidence/studio-workspace.png)에 보관한다. 전체 VoiceOver 사용성 및 다중 디스플레이 제스처 검증은 아직 수행하지 않았다.
